Find websites by name. Keep your searches to yourself.

Plumb Search is a free, open-source search engine for finding websites by name, built to run on your own machine. Type “us bank” and usbank.com comes first.

How it works

Plumb does one job: it finds websites by their names. It doesn’t index pages or answer questions, and that keeps it small enough to run on your own machine.

  • It knows names, not pages

    For each site, Plumb keeps the homepage title and description, the words other sites use when they link to it, and a few aliases. That’s about 1 KB per site, so a million sites fit in roughly a gigabyte.

  • It starts from public lists, then crawls

    Its first list of sites comes from Tranco’s top sites, Common Crawl’s web graph ranks and Wikidata’s official websites. Then Plumb visits homepages itself, to fill in titles and discover new sites.

  • It puts the real site first

    Plumb weighs how well a name matches against how well known the site is: its popularity, how many other sites link to it, and whether Wikidata lists it as an official website. That makes it hard for a look-alike stuffed with a brand’s name to outrank the real one.

  • Your searches stay with you

    Plumb runs on your own computer or server and searches its own index there, so your searches stay on your machine. There’s no account, and no one in the middle to see what you look for.

    Build from source

    Plumb is written in Rust. With Rust installed, these commands from the README build Plumb and try it on the small test dataset that comes with it.

    The README also shows how to build an index from the real public lists.

    git clone https://github.com/SueHeir/plumb-search.git
cd plumb-search
cargo build --release
alias plumb=./target/release/plumb

# Try it on the test dataset in fixtures/
plumb ingest --tranco fixtures/tranco.csv \
  --cc-ranks fixtures/cc-domain-ranks.txt \
  --wat fixtures/sample.wat \
  --wikidata fixtures/wikidata-official-sites.tsv \
  --out data/records.jsonl
plumb index --records data/records.jsonl --index data/index
plumb search --index data/index us bank

plumb serve --index data/index
# then open http://127.0.0.1:8080

Use it as your browser’s search engine

Make Plumb your browser’s search engine, and you can type a site’s name straight into the address bar.

  • Firefox can add it from any Plumb page: right-click the address bar and choose Add “Plumb Search”. To search with it by default, pick it in Firefox’s settings, under Search.
  • Chrome lists Plumb as an inactive shortcut once you have opened a Plumb page, under Settings › Search engine › Manage search engines and site search. Activate it there.
  • Any browser can take it by hand: add a search engine with one of the addresses shown here.

Search addresses

Desktop app
http://127.0.0.1:7586/search?q=%s
A server or Docker on the same machine
http://127.0.0.1:8080/search?q=%s

Your browser puts what you type in place of %s. For a server elsewhere on your network, use its address instead of 127.0.0.1.

For site owners

Plumb’s crawler visits homepages, to fill in each site’s title and to discover new sites through its links.

  • It identifies itself as PlumbSearch/<version> (+https://github.com/SueHeir/plumb-search)
  • It obeys robots.txt, including Crawl-delay.
  • It fetches one page per site: the homepage.
  • Every copy of Plumb runs on someone’s own machine and does its own crawling, so visits can come from many different addresses. They all identify themselves the same way and follow the same rules.

Roadmap

Plumb is being built in five phases. Each one ends at a test that proves it works before the next begins.

Also planned: desktops behind home routers will connect through nodes that others can reach, so nobody has to set up port forwarding.

  1. Phase 1 Now

    Prototype on one machine

    A single Plumb node builds its own index from public lists and its own crawling, and searches it locally. The test: brand names on a test list bring up the official site first.

  2. Phase 2

    Shared index between nodes

    Nodes share one index of signed records and stay in sync through daily changes. Searching over the network becomes an option, through a privacy relay (Oblivious HTTP).

  3. Phase 3

    Community crawling

    Nodes share the crawling, with random site assignments, receipts for homepage fetches and spot checks. New sites come from crawled links, Certificate Transparency logs and site owners’ submissions.

  4. Phase 4

    Private popularity counts

    Plumb learns which sites people search for and pick, without learning who: blind tokens earned by verified crawls, capped reports sent through a relay, and threshold counting. The aim is that a bot farm can’t move a ranking without doing matching crawl work.

  5. Phase 5

    Hardening

    Zero-knowledge membership if token issuers become a weak point, and a process for deciding changes to the protocol.
