# Changelog

## Unreleased

### Search

- When a homepage has no valid language declaration, a dominant non-Latin title/description script can exclude it from an incompatible language filter. Short and mixed text stays eligible. Declared languages and full typed site names are preserved. Shared scripts do not identify a language; the fallback takes effect on the next index build.

### Fixes

- A node hands the memory its threads free back to the system every five minutes instead of only after background work: a crawl round runs for most of an hour, and searches, the network and embedding free memory meanwhile, which sat unused until the system swapped it out. On Linux the node also keeps glibc's allocator to four arenas instead of up to eight per CPU, each keeping what its own threads freed (half an hour after a restart, plumbsearch.org held about 3.5 GB in 75 arena heaps), and gives buffers of 4 MB or more back as soon as they are freed. Building an index of 2.8 million sites then peaks at 1.17 GB instead of 1.31 GB and takes no longer. `MALLOC_ARENA_MAX` and `MALLOC_MMAP_THRESHOLD_` still override these.

### Crawling

- Homepage text is read in blocks. Cookie notices, browser warnings, obvious code and link menus are left out, and repeated blocks are kept once. Brief business details, mathematical prose and descriptions of policy or JavaScript products remain. Generic action labels are used only when no substantive text is available. Crawl version 2 makes nodes read older homepages again, best-known first. Inner-page fetch caches also become stale so the next fetch uses the changed text extraction.

## 0.2.1

Downloads are on [GitHub Releases](https://github.com/SueHeir/plumb-search/releases/tag/v0.2.1), and the Docker image is `ghcr.io/sueheir/plumb-search:0.2.1` (also `:0.2` and `:latest`).

### Upgrading from 0.2.0

- Docker: `docker compose pull`, then `docker compose up -d`. Desktop: install the new version over the old one. Nothing else needs doing: the index, page sets, site vectors and settings of 0.2.0 are used as they are, nothing is rebuilt for the upgrade, and 0.2.0 and 0.2.1 nodes work together in the network.
- On its first start the node removes page and place index builds an earlier run left half-done (about 4.8 GB on plumbsearch.org).
- plumbsearch.org now serves the new `subpages2` page set, so a 0.2.1 node that trusts it downloads it by itself and searches it once it is indexed: all of it, or the 100,000 most read pages under a storage limit of 1 GB. 0.2.0 nodes never ask for it, since they would list its pages without the check below. A node that fetched the old `subpages` set no longer reads `subpages.tsv.gz`: rename it to `subpages2.tsv.gz` to keep it, or delete it. The `reference` set is not shared yet and follows in a later release.

### Search

- Inner pages of well-known sites, from the new `subpages2` set of about 235 universities and labs, companies, government agencies, sports and entertainment sites and museums: a search for one page, like "amazon leadership principles" or "declaration of independence transcript", can find that page and not only the site's homepage. A page of the set is listed only when the search asks for it: it names the page by its whole title, the page is on one of the search's three best sites, or the search has at least two and three quarters of the words of its title, or of its title before a colon or " -- " (half, when the title holds all of the search's words), and no year the title lacks. So pages of big sites (CERN, Oracle, the WHO) don't come up on unrelated searches that share a word or two with them, and pages in a language other than English are left out. A page found by most of its words is kept even when the search for articles inside the query found it too.
- `plumb fetch-pages --set docs` keeps the headings of each page's sections, and a node searches docs pages by them too: with such a set, "python list comprehension" reaches Python's "Data Structures" page. A heading alone still names nothing; the search has to name the docs' product. The docs set plumbsearch.org shares does not have headings yet, so nodes search docs pages as before until it does.
- Articles whose title is only part of a search are found: "titanic sinking", "radium discovery marie curie" and "catholic homily" now reach their Wikipedia articles.
- Search by meaning reads a search after the model's instruction for search queries, and the learned ranking is retrained for it: on the half of the test searches never tuned on, the described site comes first for 49.5% of described searches instead of 47.3%, and the expected result for 76.6% of all searches instead of 76.1%. Only the default English model takes the instruction; EmbeddingGemma and embedding servers keep their own.
- Rare words and names are no longer rewritten by spelling: "perft" stays "perft" rather than becoming perf1.com's name, "Kiwipete" is not "kimipet" and "Inkala" is not "ikala". A word is now only corrected to a word that many sites or pages use and that starts with the same letter ("perft" is not "erft"), and only when the slip is likelier than the word typed as meant, counting a word no site or page has as if one did ("perft" is not "perf"), and never to one with a digit in it, whether a word or a site's name.
- A `site:` search on a docs site also finds the docs pages that match only with the product named: "asyncio site:docs.python.org" searches "Python asyncio" on docs.python.org too, so it can list the asyncio pages it missed before.
- Question pages need the word a search is about: "how to get rid of aphids" no longer lists a Skyrim question about getting rid of a bounty.
- With "Use the Plumb network" on, "weather in denver" no longer puts Spain's social security site first. Network searches no longer ask for the bucket of a small joining word ("in", "of", "the") in a longer query, and a site only the network found that lacks some of the query's words comes after the node's own results: its score was measured against the few sites the network sent, where the best partial match looks like a full one.
- A brand's sites under a country's second-level ending such as `.com.co` count as that country's, like its other country sites: pizzahut.com.co and kayak.com.co are no longer listed next to the brand's own site as if they were sites of their own.
- A small site that is a company's official one is named by the company's name, not by its address alone: "elephant valley" no longer lists Valley National Bank's valley.com.
- Site names: a site whose only Wikidata link is an inner page of it now gets its name ("Perplexity AI" for perplexity.ai), and an article no longer stands for a site on another host that it links an inner page of (the film Rocky's bit.ly link). They need the records ingested again with `--wikidata`, and the article fix needs the articles set made again.

### For AI apps

- `plumb mcp --text-answers` and `/mcp?answers=text` give each tool's answer as text alone, leaving out the same answer as JSON, which Claude Code hands the model at about twice the size. Answers are unchanged unless asked. [docs/mcp.md](docs/mcp.md) says which form each app reads, and lists Claude Code setups with `read_page` first.
- `search` takes an optional `kind` and `site`. `kind` lists one kind of result alone, best first: sites without pages, Wikipedia articles, questions, package cards, GitHub repositories, books, papers or docs pages, picked from the 200 best pages for the query rather than the 10 a search places among the sites. `site` is the same as `site:` in the query. `facts` takes an optional `more_subjects`, up to 9 more names answered in the same call, so a table of facts about several things (the Seven Summits) takes one call instead of one per row. Answers without them are unchanged, and a 0.2.0 node ignores them.
- `facts` with `about` set to `height` gives a mountain's elevation when it has no height, as search already did for "height of mount everest".
- `official_site` keeps a project's own site when its package gives only docs (pandas is pandas.pydata.org, not pandas.readthedocs.io), gives the docs when asked for them ("Pillow docs" is pillow.readthedocs.io), and keeps a well-known site's own docs ("Anthropic API docs" is anthropic.com).
- `official_site` is less often sure of a wrong answer: a site named by a name it shows nothing of, or one of two official sites of a name ("Elixir"), is no longer high confidence. A low-confidence guess gives way to a site that shows the whole name ("outlook email" is outlook.live.com, not office.com) or whose address is a word of it ("cube20 God's number" is cube20.org).
- `--mcp-findings` lets every client of a node's `/mcp` keep findings with `report_finding` and see them with search results, not only AI apps on the node's own computer. It is off by default and meant for a node whose address only trusted people have; `read_page` and sharing findings with other nodes are unchanged.

### Running a node

- Search by meaning reads the vectors file in place, mapped into memory, instead of holding a copy: a node with 2.8 million sites' vectors holds about 50 MB for them instead of 1.6 GB, and the system can drop the file's pages when memory runs short instead of swapping. Searches by meaning also take about a third less time on CPUs with AVX2, with the same results.
- Page and place index builds cut short by a crash or a restart no longer stay on disk: the node removes them when it starts. In a container, where the node has the same process id on every start, it no longer takes an earlier run's leftovers for its own.
- `plumb run --set-updates off` no longer downloads a page set the node has no file of, as it would have done with a new set such as `subpages2` once a trusted node had it. A list such as `films,map` still takes the sets it names when the node has none. A node with `all` (the default) takes missing sets as before.
- `plumb fetch-facts` reads a kind again from its start when it moves to QLever's endpoint, which lists statements in another order: facts made before lost about a third of areas, elevations and heights.
- `plumb eval --recall` shows where each test search's answer is lost before ranking: not in the index or a page set at all, too far down the sites matching its words or nearest in meaning, or never looked at by the ranking.
- The subpages set's file is `subpages2.tsv.gz`, made with `fetch-pages --set subpages2`. `subpages` still names it in settings, `--set-updates` and `fetch-pages --set`, and a size chosen for it under that name still holds.

## 0.2.0

Downloads are on [GitHub Releases](https://github.com/SueHeir/plumb-search/releases/tag/v0.2.0), and the Docker image is `ghcr.io/sueheir/plumb-search:0.2.0` (also `:0.2` and `:latest`).

### Upgrading from 0.1.0

- Docker: `docker compose pull`, then `docker compose up -d`. `:latest` and `:0.2` now name this release, and `:0.1` stays on 0.1.0. Desktop: install the new version over the old one; the node's data stays.
- The first start does some work once: sites on subdomains are folded in from the seed files the node already has, and sites read by the older crawler are crawled again, best-known first. Indexes built by 0.1.0 keep working; the next index build adds names from link text and leaves out near-copies.
- Search by meaning is now on in the desktop app and the Docker image, and downloads a 130 MB model. Turning it off in the panel is remembered.
- With no settings, searches show English sites and favor sites from the United States. The settings gear changes both.
- Crawls no longer add the new domains they find; `plumb run --take-new-sites` brings that back.
- Plugins built for 0.1.0 still run. A plugin that uses buttons, badges or response headers needs 0.2.0: build it against `plumb-plugin` with `tag = "v0.2.0"`.

### Search

- Learned ranking: the first ten results are put in order by a small model trained on the 2,463 test searches in `eval/` (never on what anyone searched). It reads what the ranking already knew about each result, such as its place, score, name match and the pages under a site, and on the half of the test searches it never saw it puts the expected result first for 83% of them instead of 74%: articles before namesake sites ("mars"), the package page for "chalk npm", the site described for "team chat". `plumb train-rank` trains it again, and `plumb eval --rank '{"learned": false}'` measures the order without it.
- Search by meaning is on by default in the desktop app, `plumb run --profile desktop` and the Docker image, as it already was on plumbsearch.org: with it, the expected site comes first for 31% of described searches ("electric car maker") on the half of the test searches never tuned on, instead of 17%. It downloads a 130 MB model and, in the network, takes site vectors from a trusted node instead of embedding them on the computer. Turning it off in the panel, which is saved, still wins.
- `--meaning-model gemma` searches by meaning with EmbeddingGemma 2 (about 310 MB, many languages) instead of the default English model. Switching models makes the site vectors again, or takes them from trusted nodes running the same model.
- Names from link text: what other sites call a site when they link to it names it, like an alias (with more weight than its domain name), once three sites or more use the words and most of the sites linking with them link there (the probability of the site given the text, as in Google's CrossWikis dictionary). So "the guardian" finds theguardian.com whatever its own pages say, while "click here" or "official website", spread over many sites, name none. Needs an index built by this version; older indexes keep working without it. `plumb eval --rank '{"link_names": false}'` measures search without it, and `link_name_bonus` sets its weight.
- Trust by accuracy (Knowledge-Based Trust, Dong et al. 2015): `plumb fact-trust` reads the text of pages in Common Crawl's WET files, finds the Wikipedia articles they name and what they say about them (a birth or death date, a lifespan in brackets, a founding year, a population, an elevation, a height, an area, a capital, a director, an author, a composer), and counts for each site how many of those match Wikidata. With `--apply` a copy of a records file gets each site's counts, and a site's link score then gains up to 0.1 for stating facts right and loses as much for getting them wrong, once at least 5 of its facts were checked: a signal that links cannot fake. Only plain mistakes count against a site: dates a year off, numbers a little off (a census a few years old) and values far off (likely another John Howard) are not counted either way. On 600,000 pages, 98.9% of 1,563 checked facts agreed, and most of the rest were real mistakes ("Sigmund Freud (1865-1939)", "Groucho Marx (1895-1977)").
- Near-copies left out: a site nobody links to whose homepage text is all but word for word that of a better-linked site in the same results (a scraped copy, a template, a mirror under a title of its own) is dropped, as found by a SimHash fingerprint of the text (Google's "Detecting Near-Duplicates for Web Crawling"). Official sites, a typed address and your country's sites stay. Indexes built before this keep working, without it, until the next build.
- Copies and one site per brand: "gmail" no longer lists gmail.ru and gmail.hu, "facebook" no longer lists a bare facebook.co, and sites that copy a brand's title are left out (23andme.org, a copy of Coinbase's). "stubhub", "search engines" and "airbnb vs vrbo" list each brand's site once instead of its country sites one after another, keeping official country sites ("cbc" finds cbc.ca) and your own country's (bbc.co.uk in the UK). A copy is still found when you type its address, and a well-known site that shares a brand's title, or has no title yet, stays.
- A name that is both a site and a much-read Wikipedia article lists the article first: "napoleon" gives the emperor before a town's site, "nikola tesla" the inventor before tesla.com and "mars" the planet before mars.com. The article has to be read far more than the one about the site, so "password manager" keeps its sites first.
- Searches that name a well-known site show less around it: "us bank" lists just usbank.com, "zoom" boxes the company instead of a 2006 film, and "amazon" shows at most two headlines about it, each story once. Little-known sign-in pages ("microsoft outlook") and pill shops named after a drug ("ibuprofen dosage") are left out unless the search names them.
- Fewer unrelated sites for a name: big sites that match none of the words no longer rank on popularity alone ("twin peaks" no longer lists wix.com), and sites with only some words of a known name are left out (twincities.com, peaks.com). Words that ask or say what is wanted ("who", "how", "best", "website", "login") no longer name a site on their own, so "who wrote pride and prejudice" no longer starts with who.int. When no result is the official site of the article a search names, that site is added ("better call saul" lists amc.com).
- Searches of two or more words no longer list big sites that share only one of the words: "secret of mana walkthrough" no longer lists victoriassecret.com, and "solar system" no longer lists systemofadown.com. A site stays when some of the search's words name it ("back bay hilton" keeps hilton.com) or it is close in meaning, so a thin search shows fewer results instead of unrelated ones. This needs search by meaning on.
- Words that say what you want keep the name: "lululemon wikipedia" finds the article, "batch normalization paper" finds the paper, and "who is galileo" and "ariana grande age" keep their info cards.
- The info card no longer goes to a namesake: "tim cook" no longer shows a historian's card, and "better call saul" no longer shows an episode's. Podcasts come after the site and the article unless the search asks for one ("podcast", "episode"), and question pages must have the search's topic word, so "how to get rid of aphids" no longer lists a game's questions.
- Medical searches ("ibuprofen dosage", "metformin side effects") list MedlinePlus, Mayo Clinic and Cleveland Clinic first, or the NHS in the UK. A well-known site the search names stays above them (diabetes.org for "diabetes").
- "news" and "world news" list well-known news sites such as nytimes.com, cnn.com and reuters.com instead of sites with "news" in their address (news.cn, news.by). A plural search that no site answers well finds the article titled in the singular ("tariffs" finds Tariff).
- Wikipedia articles are also found by their short description, their opening sentences and the other names they go by, listed after the first sites: "queen album" finds Queen (album), "manubrium" finds Sternum and "triassic jurassic cretaceous" finds Mesozoic. `plumb fetch-leads` adds the opening sentences and other names to the English Wikipedia set.
- Sites on a subdomain can be sites of their own: "hacker news" finds news.ycombinator.com instead of a look-alike, and Google Scholar, Python's docs, MDN and state DMV sites can be found.
- Better titles: results show a site's own name instead of a title borrowed from another part of it (nih.gov as "NIH Office of Disease Prevention", google.com as "Google Books"), a placeholder ("Welcome to nginx!", "Account suspended"), garbled characters or a bare "Home". A page that stands in for a site, such as an error page, an identity check or "domain is for sale", is crawled again instead of becoming its title. A site with no title takes its official name or its Wikipedia article's ("Notion" for notion.so, "National Basketball Association" for nba.com), and untitled little-known sites come after titled ones.
- A well-known site with no words of its own (no description, homepage text or Wikipedia text) can carry a one-sentence summary written by a language model, read like a description until the site has one of its own. `plumb summaries pick` lists such sites, a script in `tools/summaries/` asks Claude to write the sentences, and `plumb summaries apply` writes them into a copy of the records.
- The "search this site" box shows only when the site it names comes first and the other words are a search inside it, so "capital of ohio" no longer offers to search capital.edu.
- A misspelled site name lists the site "Did you mean" suggests in second place ("saples" lists staples.com, "tco bell" lists tacobell.com), with a link beside the suggestion ("youtbue" offers "Go to youtube.com").
- Rare words and names are no longer rewritten by spelling: "Kiwipete" is not "kimipet", "Inkala" is not "ikala", and "perft" is no longer turned into perf1.com's name. A word is now only corrected to a word that many sites or pages use, never to one with a digit in it, whether a word or a site's name.
- Spelling learned from the sites' own words (after Google's "Using the Web for Language Independent Spellchecking and Autocorrection" and Stupid Backoff): each index build pairs every word with a word one edit away found in ten times as many sites and counts what was changed as letter rules (`k` typed `ck`, a doubled letter dropped, two letters swapped), with no list of misspellings given. "Did you mean" then picks the likeliest correction by what its edits cost against how common it is, instead of fewest edits first. Two more corrections can be turned on with `--rank`: a word the index knows that is still most likely a slip of a far commoner one (`real_word_weight`), and a word the words around it show was meant as another (`context_weight`). A word that real sites use, like "inkala", is left as typed unless its correction is far likelier than the word itself. When nothing has all the words as typed and the correction does, its results are shown instead, with "Showing results for kanye west stronger. Search instead for kayne west stronger". Everyday words that no site is named for ("anubas", "budafest") are corrected from the names of pages in the page sets. `plumb spelling --index DIR` shows what was learned.
- With no settings, searches show English sites and favor sites from the United States. The settings gear changes either, and "Any language" and "Any country" still show everything. A browser that asks for another language the gear offers (`de-DE`) or names its country (`en-GB`) still gets that, a site the search names stays whatever its language ("spiegel" finds spiegel.de), and AI apps can pass `language` to `search`, English unless set.

### Answers

- The weather: "weather", "weather tomorrow", "denver weather" and "clima en madrid" answer above the results with the temperature now, today's high and low and the next three days, for a town the search names or the town you gave on About you. Forecasts come from Open-Meteo, free and without a key; the node sends only the town's rounded coordinates. "What time is it" gives the time in your town too.
- Searches for a tool or a quick fact list the sites that do the job first, under the answer when there is one: the weather service of your country (weather.gov, the Met Office, Météo-France...) and weather.com for the weather, time.is for the time, xe.com and Wise for currencies, Desmos and calculator.net for calculators, Google Translate, DeepL and SpanishDict for translations, Yahoo Finance for stocks, Speedtest for "speed test", the word's own page on Merriam-Webster, Dictionary.com and Wiktionary for "define prioritize", and Yelp, OpenTable or GasBuddy for "food near me" and "gas station near me". Before, the words matched site names: time.com for "time", eur.nl for "20 usd to eur", zaxbys.com for "food near me". `eval/utility_queries.tsv` measures them.
- Answers from Wikidata: "capital of australia", "how tall is mount everest", "when was einstein born", "ceo of apple", "who wrote pride and prejudice", "paul mccartney wife" and "atomic number of gold" are answered above the results, marked "From Wikidata", and so are other ways of asking ("nepal's capital", "what currency is used in japan"). An answer shows only when the search names an article that has the fact, once `plumb fetch-facts` has added facts to the English Wikipedia set, and AI apps and SearXNG JSON get it too.
- `plumb fetch-facts` reads a fact kind that Wikidata stopped answering on from where it stopped, after the other kinds, from QLever's copy of Wikidata (`--deep-endpoint`, `--wikidata-only`), which answers the deep pages of birth dates, deaths, populations and founding dates that Wikidata's query service times out on.
- "What is a manatee" is answered with the first sentence of the Wikipedia article, and "define anadromous" with Wiktionary's definition, on the results page and for AI apps. The info box shows the article's opening sentences too. Definitions come from the new `wiktionary` page set (`plumb fetch-pages --set wiktionary`).
- "How many ounces in a cup" is 8 fluid ounces: an ounce beside a cup, a pint or a litre is a fluid ounce.
- Unit answers are exact when the value fits in 12 digits ("1 gallon to liters" is 3.785411784 litres), and imperial fluid ounces and quarts are understood ("us fl oz to imperial fl oz").
- Searches such as "depression help" or "suicide hotline" are answered first, above every result, with free crisis lines: 988 in the US and Canada, 116 123 in the UK and Ireland, and findahelpline.com for other countries.

### Places

- Places' own sites: searches for places in a town ("brewery in denver") list the places' own websites first, even ones the index lacks (shown with the place's name, kind and address), then sites that say what was asked for, and only then sites that just carry the town's name, such as flydenver.com. When few of the places have a website on OpenStreetMap, up to six are looked up by name.
- More searches for a kind of place list places: "plumber boston open now", trades like electrician, roofer or locksmith, and "coffee open now" with no town, which looks near the town you gave on About you. "safeway near me" looks for sites as "safeway", so me.com and maine.gov no longer come up. Searches that only look like a place search no longer list places in a village or shop of that name ("toy story", "crypto exchange", "time in tokyo").
- Brewpubs and climbing gyms: "brewpub denver" (also "taproom" and "microbrewery") lists brewpubs, and "climbing gym denver" lists climbing gyms and other sports centres by their sport, also on nodes that keep only the top million places. A place tagged as a brewery counts only when it serves drinks or food, so a vet clinic no longer comes up for "brewery denver".
- Maps on real streets: with a map file from `plumb fetch-map`, the map above place results shows land, water, parks, roads, railways and town names from OpenStreetMap, in light and dark. The node draws it itself, so the page still loads nothing from other servers; without a map file it shows the pins alone, as before.
- "us bank" no longer lists banks in a town called Us: a town guessed from a query that names a site is left out. "Banks in denver" still lists them.

### Page sets

- Songs and albums: the `music` page set lists the 150,000 songs and 30,000 albums people listen to most, from MusicBrainz's data with ListenBrainz's listener counts. "hey jude beatles", "hey jude song" and "abbey road album" find them, and "bohemian rhapsody lyrics" links the song's lyrics on Genius (or searches Genius for them when MusicBrainz knows no page). No lyrics are kept. Make it with `plumb fetch-pages --set music`.
- Films and TV shows: the `films` page set lists the 150,000 films and shows Wikidata knows best, each with its year (or the years a show ran), director or creator, best-known cast and where it is listed (IMDb, Letterboxd, Rotten Tomatoes, Netflix and others). "dune 2021", "dune david lynch", "inception dicaprio", "dune movie" and "breaking bad tv show" ask for one, found as its Wikipedia article when there is one; films and shows with no English article are found by their English or original titles. Make it with `plumb fetch-pages --set films`.
- Software docs: the `docs` page set lists the pages of MDN, Python's docs, the Rust book and standard library, Node.js, React, PostgreSQL, Docker, Kubernetes, Git and 29 more docs sites, read from their sitemaps and tables of contents with robots.txt obeyed. A page is named by its product and title ("python sorting techniques", "javascript array.prototype.sort()") and also found by most of its words, like a question ("sort a list in python"). It is the first set of inner pages from good sites; each kind of site gets its own switch under Page sets. Make it with `plumb fetch-pages --set docs`.
- Inner pages of well-known sites: the `reference` page set holds pages from about 150 reference sites (health, dictionaries, recipes, how-tos, money, government, law), and the `subpages` set pages from about 235 universities, companies, government agencies, sports and entertainment sites and museums. A search for one page, like "irs form 1040", can then find that page and not only the homepage. Make them with `plumb fetch-pages --set reference` and `--set subpages`.
- Questions of 33 more Stack Exchange sites: the `stackexchange` page set lists the most viewed questions of Super User, Ask Ubuntu, Home Improvement, Seasoned Advice, Travel, Personal Finance and others, so "how to unclog a drain" finds the Home Improvement question. Make it with `plumb fetch-pages --set stackexchange`.
- A Stack Overflow or Stack Exchange question is also found by the titles of up to three questions closed as its duplicates; `plumb fetch-pages --set stackoverflow` downloads Stack Overflow's 150 MB list of links between questions for this.
- Free copies of papers: a paper that can be read free says so under it, "Free to read on arxiv.org", linking its arXiv copy, the publisher's open version or a repository's copy (from OpenAlex, which carries Unpaywall's data), and AI apps get it as `free_copy`. With `CORE_API_KEY` set, `plumb fetch-pages --set papers` also asks CORE's university repositories about the papers OpenAlex knows no free copy of, a few tens of thousands a day, keeping what it found for later runs. Fetch the papers again to get them.
- Papers by title and short name: a paper's whole title of four words or more ("basic local alignment search tool"), its title with the first author, year, venue or "paper" ("random forests breiman"), or the short name it goes by ("bert paper", "yolo paper", from the Papers with Code archive) puts the paper first. Well-known arXiv papers that OpenAlex lacks are added from arXiv, and papers OpenAlex credits with implausibly many citations for their age are left out. Fetch the papers again to get them.

### About you, history and tuning

- About you for everyone: the home page invites a new searcher to `/welcome`, which asks for a city, topics to tick (cooking, soccer, programming...), anything else they care about and sites they like. `/about` is the same page later, with sites never shown and "Forget all of this". Both work on servers that keep no search history, where the browser keeps the profile in a cookie and the server keeps no copy.
- Each kind of result can be turned off, down or up: About you has Off, Less, Normal and More for Wikipedia articles, films and TV, songs, podcasts, books, papers, Stack Overflow, GitHub, packages, docs and the other kinds.
- One profile on all your browsers and nodes: the `/link` page, linked from History and About you, makes a code that works once, for 10 minutes. Pasted in another browser on the same node, it switches that browser to the profile; pasted on another of your nodes, the two keep their copies of history, About you and what was learned alike, until either stops sharing. Public servers keep no profiles.
- Edit mode ("Edit these results" on a results page): small buttons put a result higher or lower for that search or hide it from that search, and fold places or headlines for that search or every search like it. What you say wins over what your clicks say.
- Tune your search (`/tune`): go through five random searches on the real results page in edit mode, and Plumb learns from the results you move up or down and hide what kinds of result you like (official sites, encyclopedias, forums, code, video, shops, social media, news, government and schools, small or well-known sites, your country's) and whether maps and headlines help you, then leans every search that way. A kind counts only when results of that kind were moved up (or down) clearly more often than the other results on the same pages, so hiding a few off-topic results no longer reads as disliking every kind they belong to. `/tune` and `/history` say what it learned.
- Learning from clicks, on the node for each browser with search history on: places and maps you seldom open for searches like one you make are folded to one line, "Recent" headlines you often read come unfolded, and sites you always pass over move down a little. `/history` shows what was learned and forgets it; the settings gear turns it off.
- Sites opened before also come up for searches that share words with the one they were opened for ("us bank login" after "us bank").
- Clicks count for where they were: a site opened from far down the results page now lifts searches like that one more than a site opened first, which is opened largely for being first ("Position Bias Estimation for Unbiased Learning to Rank in Personal Search", Wang et al. 2018). The node counts, for browsers that learn from clicks, how often results are opened at each place, as counts under a salted fingerprint with no profile, search or site in them, and works out by EM how much each place is looked at; until it has 100 clicks it assumes `1 / place`.
- Searches as training examples, if you choose: "Use my searches to train Plumb's ranking" in the settings gear (off unless chosen) keeps your short searches and the sites you open for them on the node, with no profile, and `plumb click-labels` writes them out with click rates corrected for each result's place, plus a queries file of the searches whose clicks clearly pick one site, ready for `plumb eval --features-out` and `plumb train-rank`.
- Ranking experiments: an `experiments.json` in the data folder tries ranking changes on a share of the node's searches, in layers that overlap independently (Tang et al. 2010), and counts for each experiment how many searches had a result opened and at which place. `plumb experiments --data DIR` compares each with its control, with confidence intervals.
- Saving About you and clearing search history work in browsers and the desktop app, where they were refused with "Pages of other sites cannot change this."

### For AI apps

- `facts`, a new MCP tool: what Wikidata says about the thing a name names (capital, population, born, CEO, founder, coordinates, atomic number and the rest of the 25 kinds Plumb keeps), one line per fact with the Wikidata item and property it is from, so an AI app can cite a fact instead of answering from memory. `about` asks for one kind (`ceo`, `capital city`).
- `official_site` gives fewer confident wrong answers. It takes the site Wikidata gives for the name's Wikipedia article, including subdomains and inner pages (MathWorld is mathworld.wolfram.com), sends "Python docs" to docs.python.org, puts a package's own site above one that matches only by its address, and answers with low confidence when only a similar name or part of the name matches. `site_info` says when a subdomain is counted as part of its parent site.
- `read_page` takes `outline: true` and returns the page's headings instead of its text, each with where it starts and its opening words, so an agent can read only the section it needs. `eval/llm/bench.py --mode outline` measures what that saves against `--mode plumb`.
- On a node run with `--mcp-read-pages`, apps on other computers can have `read_page` read pages only on the usual web ports (80 and 443, redirects included), under a rate limit of their own. `search` suggests `read_page` only where the node offers it.
- Install commands such as "cargo add serde", "pip install requests" or "npm i -D vitest" show the package's card.
- `read_page`, `report_finding` and `check_lookalike` keep long addresses whole (up to 4,096 characters) instead of cutting them at 200. SearXNG clients paging past the last page get an empty page, and a client that searches the network too often gets 429 with Retry-After.
- Shared findings: on a node run with `--share-findings`, an AI app can share a page it found useful with other Plumb nodes (`report_finding` with `share: true`), and an agent searching another node for the same thing gets it as a lead, with which nodes reported it, when, and until when. A lead carries the page and why it helped, signed by the node; not the answer or the task, and the search only as numbers unless the agent shares it too. Leads are listed apart from the results as unchecked, only from nodes in the search scope, and every node keeps at most 20,000 for 30 days. Off by default; findings an agent does not share stay on its node as before.
- Relations as vectors (an experiment): `plumb relations` learns each kind of Wikidata fact that links two things (capital, founder, CEO, headquarters...) as a map between the EmbeddingGemma vectors of their Wikipedia articles, and `plumb mcp --relations DIR` offers a tool `relate` that follows a relation, or a chain of them ("headquarters > capital"), in one call, with a probability for each answer and whether Wikidata states it, or says how likely a claim is. The maps start from plain closeness and learn the difference: on held-out facts the right object comes first 49% of the time for headquarters instead of 16%, 31% for founder instead of 16%. `eval/llm` measures whether Plumb's tools help a small local model answer SimpleQA and HotpotQA, and at what cost in context.

### Plugins

- Plugin interface 2 (older plugins still run): results can carry badges, pictures, magnet links and up to three buttons that only the node's owner can press, and a plugin can add a badge or buttons to the node's own results or leave a result out. Plugins also see response headers and the Wikidata item a search is about. A `hosts` entry without a port now allows only ports 80 and 443; add the port to reach another (`127.0.0.1:7878`).
- A search that fits a plugin without naming its keyword ("radiohead", "dune trailer" for YouTube) can run it, show a "Show results from YouTube" link, or do nothing. You choose for each plugin under Search, Plugins in the panel (plugins declare `hints` and `suggest` in `plugin.json`).
- A YouTube plugin (`plugins/youtube-music`) that uses your own free YouTube API key: `ytm creep` or "creep youtube music" lists songs that open in YouTube Music, and `yt rust async` lists videos, channels and playlists. It uses only YouTube's official API.
- Songs on YouTube: with the YouTube plugin installed, a search for a song or album the node knows ("creep", "kanye west gold digger") shows it from YouTube Music beside the node's results, searched for by its artist and title. A title alone counts when one song of that title is far better known than the rest ("creep" is Radiohead's, "hello" is no one's) and no site or article is called just that (a namesake such as "Creep (2014 film)" does not count); it still lists no song. Artists and other searches that fit still show a "Show results from YouTube" link, to save the key's quota. Plugins can list such identifiers as `run_ids`, and learn a song's or album's artist as `about.by`.
- A Reddit plugin (`plugins/reddit`) that goes through Reddit's official API with your own app's keys, which Reddit has to approve first. A search that starts or ends with "reddit" lists threads with their subreddit, points and comment count, and "reddit r/rust async" searches one subreddit. Adult threads show only with safe search off.
- GitHub and Steam plugins: `gh http client` or "tokio github" lists repositories with their stars, language and last push, and with a token gives you Star and Unstar buttons. `steam portal` finds games in your Steam library with hours played, and results about a game you own or wish for get a badge ("Owned, 25 h").

### Crawling

- New sites are held back: crawls refresh the sites a node holds and no longer add the domains they find linked, and records other nodes share only refresh sites already held, while the network makes the sites it has searchable first. Filling free space from trusted nodes, the seed and searches still add sites the network knows. `plumb run --take-new-sites` adds new sites as before.
- Each crawl round first fetches up to 500 well-known or official sites that no crawl has reached yet, whether or not they are in the node's share, so sites like weather.com and state.gov are read sooner. They come out of the round's usual budget.
- Words from the whole homepage: each crawl picks the 30 words that best describe a site from up to 1,000 words of its homepage, and searches match them, so "team chat" can find a site whose homepage says so but whose name does not.
- Many more sites are marked official: nodes and `plumb fetch-data` take the official website of every Wikidata item with Wikipedia articles in at least 3 languages, about 627,000 sites instead of 131,000, so Expedia, Indeed and Instacart get the mark, Wikidata's description and facts. The list comes first from QLever's copy of Wikidata, which answers in seconds; `plumb fetch-data --no-wikidata-mirror` asks only Wikidata.
- Dead sites: `plumb run --drop-dead-sites` takes sites out of the index that no crawl has reached for 60 days after 6 tries in a row that got no answer. Never the best 10,000 sites, official websites or ones you chose. A dead site keeps a small record and comes back when it answers again. Off by default; without it the node only counts them in its log, and `plumb dead-sites --data DIR` counts them without changing anything.
- Site names from schema.org: crawlers read the names a homepage gives its own site in JSON-LD (the `name`, `alternateName` and `legalName` of its `WebSite` and `Organization` items, such as "BofA" or "Bank of America Corporation") and keep them as the site's aliases, so a site whose visible text is all menus can still be found by what it calls itself. Items about other sites (a publisher, a partner) are skipped, and crawlers have to agree on each name as on any other.
- Reading sites anew: when crawlers learn to read more from a homepage, the crawl version goes up and nodes crawl the sites read by an older crawler again, best-known first.

### Nodes

- Much less memory: crawl rounds keep about 150 bytes of each site instead of its whole record, and index builds, search by meaning and the network's records read the records file a record at a time. With two million sites a crawl round holds about 300 MB of site data instead of 3 GB or more, and an index build about 0.6 GB instead of about 5 GB, so a 4 GB server runs a node. `plumb index` reads a record at a time too.
- A node can pick its search pages' starting settings: `plumb run --only-country` starts them with "Only this country" on, and `--lang en` with English whatever the browser's language. The settings gear still changes both, and the JSON API and `/mcp` still give every country's sites. plumbsearch.org starts with the United States, only its sites, and English.
- `plumb run --network --crawl-only` is for small servers: the node crawls its share of the sites and publishes each batch, but builds no search index, answers no searches and takes in no other node's crawls, so it needs far less memory.
- Nodes with a storage limit, such as the desktop app, stay closer to it: the places file keeps the first million places and those within 100 km of the towns on About you, and other crawlers' batches take at most a fifth of the limit, oldest dropped first.
- The records' journal is folded into the file at every index build, and once it reaches 128 MB, so it no longer grows for days on a big node.
- Big nodes keep answering searches while they rebuild the index and embed sites: builds and embedding run at a lower priority than searches, rebuilds for records from the network wait longer, and status requests and searches no longer wait while the node measures its data folder.
- Network searches no longer wait out a slow or gone node: a bucket still short of two answers after a quarter of the wait (or as soon as its requests failed) is asked of one more node, and the search returns once every bucket has two answers. `/api/network/search` counts these requests as `hedged`.
- Nodes that join the network at the same moment, as they all do after the bootstrap node restarts, find each other within seconds instead of up to five minutes.
- Page sets and the map file stay up to date from trusted nodes: every six hours a node takes the newest file a trusted node has of each set it keeps and keeps its own as `.prev`, but not a file far bigger than its own or missing kinds of entries its own has. `plumb run --set-updates off` stops these updates, and a list such as `films,stackoverflow,map` updates only those.
- Page sets download more reliably: a node searches the sets it already has while others download, asks the next trusted node when one lacks a set, and no longer lets one set it cannot get hold up the rest. The list of adult sites that safe search leaves out comes from a trusted node too.
- Restoring a backup from the panel works while the node is on the network, and pausing the node and the daily download limit also cover page-set, site-vector and meaning-model downloads.
- A node started from a copy of another node's data folder, which carries that node's network identity, stays off the network with a warning unless started with `--network`, and then names the file to delete to get an identity of its own.
- Index builds no longer leave unused files in the data folder (369 MB on one desktop), failed builds no longer leave half-written ones, and a paused node no longer checks its feeds every second.

### Desktop and web pages

- Redesigned the desktop and shared search UI with Search and Settings navigation, warm surfaces and navy controls. Desktop searches now stay in the app; result links open in the usual browser. Node settings include AI integrations and installed plugins. The website shares the design, and a geometric P replaces the old logo across platforms.

## 0.1.0

The first release. Downloads are on [GitHub Releases](https://github.com/SueHeir/plumb-search/releases/latest), and the Docker image is `ghcr.io/sueheir/plumb-search:0.1.0` (also `:0.1` and `:latest`).

### Search

- Homepage search: sites by name, homepage title and description, and the words other sites link to them with. Official sites come first, and look-alikes stuffed with a brand's keywords stay below the real one.
- Page sets next to sites: English Wikipedia, Stack Overflow's most viewed questions, Open Library's most read books, the most cited papers, well-starred GitHub repositories, Podcast Index's most popular podcasts and the most used packages of eight registries. Only titles, short descriptions and counts are kept.
- Instant answers (sums, unit and currency conversions, the time in a place), info boxes with official sites, profiles and where a film, show, game or album is listed, and sitelinks.
- Places from OpenStreetMap, with a map drawn from coordinates.
- Recent headlines from the RSS and Atom feeds of the best-ranked sites.
- Search operators, safe search, language, spelling suggestions and optional search by meaning.
- Private search (`/private`): the browser fetches padded buckets and ranks them itself.
- Search history and "About you" interests, kept on the node for each browser; off on public servers.

### Network

- Peer-to-peer network: each day every node crawls a random share of sites, signs each batch, and checks other nodes' batches before taking them in. Nodes behind home routers need no port forwarding.
- New nodes set up from a trusted node's sites in minutes, and keep under a storage limit.
- Network search without sending the query: hashed buckets, padded, through a relay, with a Merkle proof on every result.
- Crawl credits and anonymous tokens that buy priority when a node is busy.

### For AI apps

- MCP server at `/mcp` on every node and `plumb mcp` over stdio, with `search`, `official_site`, `check_lookalike`, `site_info`, `package`, `read_page` and `report_finding`.
- SearXNG-compatible JSON at `/search?format=json`, and Open WebUI's external search at `/api/websearch`.

### Running it

- Docker image for Linux on x86 and ARM, and a desktop app for Windows, macOS and Linux with a settings panel and control of other nodes.
- Plugins: results from other sources, written in Rust and run in a WebAssembly sandbox.

### Security fixes from the pre-release audit

- The crawler refuses private network addresses, including in redirects, icons and feeds.
- Tools and pages meant for the node's own computer check where requests come from more strictly, including requests passed on by a proxy and DNS rebinding.
- Per-client limits for MCP and network search, counting clients behind a local proxy correctly.
- Requests sent by other sites to the node's own forms are refused.
- Tighter limits on a few inputs and on what plugins can write to the log.
- A crawl found by a network search is kept only when its crawler is trusted or confirmed by others, so one new key cannot rewrite a site's title.
- Network searches ask only nodes that take sealed requests when relays are available, and nodes limit connections and how much they serve at once.
- Feeds are read without document type definitions, so a feed cannot expand into gigabytes.

### Fixes from the pre-release audit

- Searches with curly quotes, and a few calculator and time-zone inputs, no longer fail.
- On nodes with a storage limit, the places file is no longer cut at every start, and trimming never drops more sites than it can free.
- Unit symbols keep their case (`mW`, `Gb`), and `gr` is grain.
- robots.txt redirects to another host are followed, and large downloads resume.
